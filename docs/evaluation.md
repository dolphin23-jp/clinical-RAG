# 評価と測定の手順（T1-7 数値の転写誤り率・T1-8 臨床版の評価セット）

状態: **道具は実装済み（2026-10-24）。測定・評価そのものは、まだ（医師の作業が要る）**。設計は `docs/enhancement-plan.md` の T1-7・T1-8。**iPad だけで行うときは 5**（アプリの「測定・評価」の画面。PC の道具は 1〜3）。

## 0. 何のために測るか

| | 測るもの | 決める材料にすること |
|---|---|---|
| T1-7 | 用量・閾値などの**数値の転写の誤り率**（書籍別・旗別） | 頁画像との全数照合（B3）に投資するか。どの本から照合するか |
| T1-8 | 先生の実際の質問での**検索と回答の質**（取りこぼし・正解頁への引用・「書籍にない」と言えるか） | 辞書（T1-9）の効果と重みの調整、埋め込み（A3）に進むか、プロンプトの見直し |

README にある「0.7〜6%」は**頁マーカーの読み違い**の率で、数値の誤り率ではない `[確認]`。数値の誤り率は、まだ誰も測っていない `[未確認]`。

## 1. 準備（共通）

- Node 22 以上、Python 3.11 以上。`worker/` で `npm ci`。本番の D1 を読むときは `npx wrangler login`（取り込みのときに済んでいれば不要）
- アクセストークンは**環境変数 `MEDBOOK_TOKEN`** に入れる（Worker の `APP_TOKEN` と同じ値）。コマンドの引数には書かない（履歴に残るため）
  - PowerShell: `$env:MEDBOOK_TOKEN="（トークン）"`
  - mac / Linux: `export MEDBOOK_TOKEN=（トークン）`
- 出力は `work/`（`.gitignore` 済み）か、リポジトリの外に置く。書籍の抜粋を含むので、リポジトリには入れない（4）

## 2. T1-7 数値の転写誤り率

### 2.1 抜き取る

```bash
python scripts/sample_numeric.py sample --d1 medbook          # 本番の D1（全書籍）。おすすめ
python scripts/sample_numeric.py sample --db work/library.sqlite   # 手元の SQLite（取り込みのたびに作り直され、その回の本だけ）
```

- 既定は 40 チャンク・1チャンクから最大 3 行（`--chunks` `--per-chunk`）。同じ `--seed` なら同じ標本になる。`--books id1,id2` で本を絞れる
- 抜くのは、取り込みで数値の旗（`numeric_critical`。用量の単位か、検査値の閾値）が立ったチャンクのうち、**書籍の本文だけ**（転写者の補助・文献リストは除く）。**書籍ごとに均等**に割り付け、その中で「用量の単位」と「検査値の閾値」に均等に分ける
- 1行は「数値＋単位」か「比較つきの数値」（`< 20`、`30 未満` など）。頁番号・図表番号・年・単位のない数値は行にしない
- 出力は `work/numeric_sample.csv`（Excel で文字化けしない UTF-8。リポジトリの中では `work/` 以外に書かない）

### 2.2 記入する（頁画像と見比べる）

| 欄 | 書くこと |
|---|---|
| 判定 | **一致** / **誤り** / **判定不能**（○・×・? でもよい） |
| 正しい表記 | 誤りのとき、原本の表記 |
| 誤りの種類 | 桁 / 小数点 / 単位 / 範囲 / 記号 / その他 |
| 頁ずれ | **はい**（その頁に数値がなかった）/ いいえ |
| メモ | 自由 |

- 見るもの: 頁画像（R2 に入っていれば、アプリの根拠シートの「原本 p.N」。なければ PDF か本）。「前後の文」の【】が対象の数値
- 判定の基準: 数字・小数点・単位・範囲・不等号が原本と同じなら**一致**。OCR の頁がずれていても、数値が正しければ一致にして、頁ずれを「はい」にする（頁の誤りは、引用の頁の正しさの問題として別に数える）。原本で読めないときは**判定不能**

### 2.3 集計する

```bash
python scripts/sample_numeric.py report work/numeric_sample.csv
```

書籍別・旗別の誤り率と 95% 信頼区間（Wilson 法）、チャンク単位の率、誤りの種類、頁ずれの率を出す。

### 2.4 読み方と、決めること

- **0 件は「誤りがない」ではない**。100 行で誤りが 0 件でも、95% 信頼区間の上限は約 3.7% 残る。行を増やすと区間は狭くなる
- 本ごとに差が大きければ、誤りの多い本だけを先に頁画像で照合する（B3 を全書籍に広げない）
- **どの率なら B3 に進むかは、先生が決める**（作成者は閾値を決めない）

### 2.5 限界

- 抽出は「単位つき」か「比較つき」の数値だけ。単位のない検査値（「Na 140」）は行にならない
- 旗は取り込みの経験則で、見逃しも過検出もある。旗のない節の数値は、この測定の外
- 標本は書籍ごとに均等に割り付けたもので、全体の率は書籍の大きさで重み付けしていない（書籍どうしの比較が目的）
- 目視の見落としは測れない

## 3. T1-8 臨床版の評価セット

### 3.1 質問を書く

1. `eval/clinical.template.jsonl` を `eval/clinical.local.jsonl` にコピーする（`*.local.jsonl` は `.gitignore` 済み）
2. 例の行を消して、**30〜50 問**書く。欄の意味は雛形の冒頭にある
3. **入力の約束**（`docs/clinical-use.md` の 2）に従う。実臨床で考えた問いから作るときも、年齢（歳の整数）・主要所見・検査値の数値までに抽象化する。識別情報らしき文字や、雛形の例のまま（`BOOK_ID`・「（先生が書く…）」）の行があると、道具は行番号を示して止まる
4. **正解（gold の頁・必須語）は、先生が書籍で確かめて書く**。作成者は臨床の正解を作らない
5. **検索結果を見る前に書く**（見てから書くと、当たる問いばかりの甘い評価になる）

入れてほしい問い: 取りこぼし事例（高K血症で聞いて透析の適応・カリウム吸着薬の節に当たるか、意識障害で AIUEOTIPS の節に当たるか）、略語と日英、数値の問い（gold は頁で）、複数の本にまたがる問い、手元の書籍にない問い（`"negative": true`）。外すと判断が変わりうる問いは `"severity": "high"`。

### 3.2 検索の評価（LLM を呼ばない。無料・1日の上限に数えない）

```bash
node --no-warnings eval/run_eval.ts --api https://<worker> eval/clinical.local.jsonl --compare-dict
node --no-warnings eval/run_eval.ts work/library.sqlite eval/clinical.local.jsonl   # 手元の SQLite でも（その回の本だけ）
```

- 各問の順位（`@1` / `MISS` / `neg`）、外れた問いの上位 3 節、組・重要度ごとの hit@1・hit@3・hit@5・MRR
- `--compare-dict`: 辞書（`worker/src/synonyms.ts`）あり・なしの比較と、**順位が変わった問い**の一覧
- 正解の判定: 返った節が `expect` の条件をすべて満たすか（頁が節の頁の範囲に入る・本が一致・本文に語がある）。`--api` では、本文を `/api/parent` で取って調べる
- `--verbose` で、当たった問いの上位 3 節も出す

### 3.3 回答の評価（モデルを呼ぶ。費用がかかり、1日の上限に数える）

```bash
node --no-warnings eval/run_ask_eval.ts --api https://<worker> eval/clinical.local.jsonl --max 10        # 計画を出して止まる
node --no-warnings eval/run_ask_eval.ts --api https://<worker> eval/clinical.local.jsonl --max 10 --yes  # 実行
```

- 1問ずつ `/api/ask` に送り、結果（最後まで回答・縮退・エラー・識別情報で拒否・上限）、書籍の引用の数、**正解の頁に引用が付いたか**、**必須語が出たか**、書籍にない問いで**「見つからなかった」と言えたか**を記録する
- 結果は `work/ask_eval/<時刻>.jsonl`（回答の本文を含む。`.gitignore` 済み）。重要度 high で外れた問いを最後にまとめて出す
- 費用は 1問 5〜15 円の概算（README。未実測）。1日の上限（`DAILY_ASK_LIMIT`）に達したら、そこで止まる。`--only id1,id2` で問いを絞れる。`--web` `--model` も渡せる

### 3.3b 文章からの取り込みの評価（モデルを呼ぶ。費用がかかり、1日の上限に数える）

```bash
cp eval/extract.template.jsonl eval/extract.local.jsonl     # 先生のメモの型で書き直す（*.local.jsonl は .gitignore 済み）
MEDBOOK_TOKEN=... node --no-warnings eval/run_extract_eval.ts --api https://<worker> eval/extract.local.jsonl --verbose --out work/extract_eval.json
```

- 1件ずつ `/api/extract` に送り、返った提案を `expect`（そのメモが支える答え）と `must_not`（支えない質問）に突き合わせる。**的中・欠落（missing）・誤り（wrong: 別の値）・余計（extra）・forbidden（`must_not` への提案）**を数える（`docs/enhancement-plan.md` の 8.12 の6 の型別の数え方の入口）
- **forbidden が1件でも出たら、終了コード 1。目標は 0**（書かれていない所見の「なし」化・指示の「実施済み」化。Modules と同じ基準）。出たら、そのメモとモデルの指示の規則（`worker/src/extract.ts` の `buildSystem`）を見直す。wrong は次に悪い。missing（1タップの手間）と extra（画面の確認で見られる。正しいこともある）は先生が判断する
- メモは、先生が実際の書き方の型から**架空に書き直したもの**（氏名・ID・日付なし）。実際のメモそのものをこのファイルに入れない（`docs/clinical-use.md`）。結果は `work/` に出す（`.gitignore` 済み）
- 同じ場面・症候の2件目からは、指示と質問の一覧がキャッシュから読まれる（`usage.cache_read_input_tokens`。1件目だけが書き込み）。待ち時間（ms）も出る

**Worker をデプロイせずに測る（`--local`）**

```bash
ANTHROPIC_API_KEY=... node --no-warnings eval/run_extract_eval.ts --local eval/extract.invented.jsonl --verbose --out work/extract_eval.json
```

- Anthropic API に直接つなぐ。指示・スキーマ・答えの検査は Worker と**同じコード**（`worker/src/extract.ts`）なので、モデルの振る舞いと、検査が残す割合（`dropped` の数も出る）は同じに測れる。測れないのは Worker の経路（合言葉・1日の上限・Worker の環境変数 `EXTRACT_MODEL`）で、そちらは上の `--api` で確かめる。`MEDBOOK_TOKEN` も、デプロイも要らない。1日の上限には数えない
- 鍵は環境変数だけ（既定 `ANTHROPIC_API_KEY`。別の名前なら `--key-env NAME`）。画面にも `--out` にも出さず、Anthropic の API 以外へ送らない（テストが検査する）。モデルは `--model`（既定は `EXTRACT_MODEL`、なければ Worker の既定の `claude-sonnet-5-5`）
- 結果には、入力・出力・キャッシュのトークン数、1件あたりの時間（平均と最大）、答えたモデルが出る。費用は、これと API の料金表から先生が見積もる（ここでは金額にしない）
- `eval/extract.invented.jsonl`: 作成者が新しく書いた架空のメモ15件（呼吸困難・胸痛・失神・発熱・頭痛。支えるもの、否定、予定・指示、疑い、一部だけ聞いた陰性、別の人の情報、2つの姿勢の血圧、2つの体温）。**最初の1回を、先生のメモなしで測るためのもの**で、先生の書き方の測りではない（先生の書き方は `extract.local.jsonl` で測る）。`worker/test/extract-cases.test.ts` が、全ての質問・選択肢・数値・時刻が質問の一覧とメモに合うことを検査する（id の綴りの誤りは、的中しない「欠落」として紛れるため）

### 3.4 読み方

| 見えたこと | 次の手 |
|---|---|
| ある組の hit@3 が低い | 辞書に語を足す（医師の確認なしでよい）。足りなければ埋め込み（A3）を検討 |
| 辞書ありで順位が**下がった**問い | 辞書の語が雑音になっている。その群を見直す。重み（`SYNONYM_WEIGHT` 0.5、`RELATED_WEIGHT` 0.3）の調整もここの数字で |
| 正解の頁に引用が付かない | 検索で当たっていない（3.2 で MISS）のか、当たっているのに回答で使っていない（プロンプト）のかを、3.2 の結果と突き合わせて分ける |
| 書籍にない問いに答えてしまう | 「見つからなかった」と言えていない。プロンプトの検索の規律を見直す |

### 3.5 限界

- 正解の判定は節の単位で、節のどこに答えがあるかは見ない
- 必須語は文字の一致で、言い換えは数えない（外れた語は、回答を読んで確かめる）
- 回答は同じ質問でも揺れる。1回ずつの評価なので、大事な問いは複数回見る
- 偽の API を使った試験（`worker/test/eval.test.ts`）は、道具の配線を確かめるだけで、モデルの質は測らない

## 4. 保存してよいもの

- リポジトリに入れる: 雛形、道具、この文書
- **入れない**: 質問ファイル（`eval/*.local.jsonl`）、作業表（`work/numeric_sample.csv`）、回答の記録（`work/ask_eval/`）。書籍の抜粋や、実臨床由来の問いを含みうる
- iPad の画面: 作業表と判定は端末の中だけ、評価の質問は D1（`eval_questions`）、回答と評価の結果はどこにも保存しない（5、`docs/clinical-use.md` の 1c）
- 結果を記録に残すときは、数字だけを書く（書籍の文や質問の文は書かない）

## 5. iPad だけで行う（アプリの「測定・評価」）

ヘッダーの ☑ のボタンで開く。PC も Python も Node も要らない。保存先は医師の決定のとおり（`docs/clinical-use.md` の 1c）。

### 5.1 数値の照合（T1-7）

1. 「作業表を作る」（抜く節の数・1節あたりの行の上限・seed）。本番の索引から、PC の道具と同じ設計（書籍ごとに均等、その中で用量と閾値に均等）で抜く。**同じ seed でも、PC の道具とは別の標本になる**（乱数の作り方が違う）。1回の測定には、どちらか一方を使う
2. 各行の【】の数値を、「原本 p.N」（頁画像が登録されていれば）か本と見比べて、**一致・誤り・判定不能**を押す。誤りなら種類と正しい表記、頁がずれていれば「この頁に数値がなかった」。「節の全文」で前後も読める
3. 記入は押すたびに**この iPad の中に保存**される（閉じても、アプリを開き直しても続きから）。サーバーには送らない。アプリを削除すると消える。「未記入だけ」で残りを絞れる
4. 「集計」で、PC の `report` と同じ集計（書籍別・旗別の誤り率と 95% 信頼区間、誤りの種類、頁ずれ）が出る。結果は数字だけを伝えればよい
5. 終わったら「作業表を消す」で端末から消せる

### 5.2 評価セット（T1-8）

1. 「問いを追加」: 質問（ふだん打つ形の文）、検索の語（1行に1つ）、重要度、組、書籍にない問いか、正解の本・頁・節にある語、回答に出てほしい語。**「頁を探す」**で検索（LLM なし）し、結果を押すと本と頁が入る
2. 保存すると**サーバー（D1）**に置かれる。識別情報らしき文字や雛形の例のままの問いは、理由を示して保存しない。編集・削除は一覧から
3. PC で書いた問いは「まとめて取り込む」に貼る（同じ形式。1行でも問題があれば何も取り込まない）。「JSONL をコピー」で PC の道具に持っていける
4. 「検索を評価（無料）」: 1問ずつ本番の索引で、辞書あり・なしを比べる（LLM なし。1日の上限に数えない）。組・重要度ごとの hit@1・hit@3・hit@5・MRR、辞書で順位が変わった問い、外れた問いの上位の節
5. 「回答を評価（費用あり）」: 最初の N 問を送る。押すと問数と費用の目安が出て、確かめてから送る。1日の上限に数え、上限に達したら止まる。結果（引用・正解の頁・回答に出てほしい語・「見つからなかった」）は**この画面のメモリだけ**で、保存しない

### 5.3 限界（iPad の画面に固有のもの）

- 作業表の記入は端末の中だけなので、別の端末では続けられない。端末の保存領域が消されると記入も消える（ホーム画面に追加したアプリの保存の扱いは iOS の仕様に依る `[要確認]`）
- 回答の評価の結果は保存しないので、画面を閉じると消える。数字は閉じる前に控える
