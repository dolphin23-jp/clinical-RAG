**症例モードの細目（作成者の案。実装済み。変えたいときは言ってください）**

- 入口はヘッダーの「症例」。年代（10歳刻みの選択。乳児・幼児・学童は別の区分）・性別・場面（外来・救急・病棟）・主訴と経過・バイタル・身体所見と検査・既往と内服・先生自身のアセスメント（任意）。固定すると画面の上に1行で残り、質問のたびに自動で付く（「質問に付ける」で切れる）。症例は最後の質問にだけ付け、履歴には入れない（費用が伸びない）
- 4つの依頼（アセスメントとプラン（草案）／鑑別と反証／見落としチェック／コンサルト・医師コールの基準）は固定の見出しで出る。症例を付けた自由な質問も、同じ症例の前提で答える
- **識別情報のガードは、症例のすべての自由記述の欄にかかる**（入力中の警告、送信前の確認、サーバーの入口、保存の入口）。日付は経過で書く（2.1）。稀な組み合わせは一般化して入れる（2.2）
- 症例は、**会話の往復に付けて保存される**（`payload.case`。1d の①と同じ保存先・同じ期限・同じ削除）。ブラウザの保存領域には置かない。会話を開き直すと、その会話で最後に付けた症例が固定し直される。「新しい会話」は症例を外す（まだ質問していない症例は保存されていないので、確認を出す）。識別情報の確認を通した質問は、症例ごと保存しない
- 出力は草案: 画面に「草案・最終判断は医師」。コピーした先頭にも印が付く。書籍から書いた文は引用の印、引用のない文は `[推論]` `[標準・出典未確認]` `[施設依存]` のいずれかを付けさせる。薄い表示と数値の突き合わせは、そのまま効く（症例に入力した数値は突き合わせの対象外）
- **「先生の案との差」は、自分のアセスメントを入力したときだけ**。違いを並べるだけで、正誤・点数・評価は付けない
- プロンプトの書きぶりは、**本物の API でまだ確認していない**（開発環境に鍵がない）。マージ後の最初の数例で、医師が見出し・印・反証の書きぶりを見る

**カルテ記載の下書きの細目（作成者の案。実装済み。変えたいときは言ってください）**

- 入口は2つ。アセスメントとプラン（草案）の項目の「採用」→ 回答の下の「記載の下書きを作る」。固定した症例の横の「記載」（症例の入力だけで作る）。**採用は、アセスメントとプランの草案だけ**で、問題リスト・各問題の評価・初期プラン・コンサルト・医師コールの基準の項目（箇条・段落・表の行）に付く。草案自身についての節（確認すべき数値・書籍に見つからなかった点・先生の案との差）には付かない
- 型は、clinical-modules の記載の型から**欄の名前・順序・必須か条件つきか・版だけ**を取り込む（`scripts/import_note_types.py`。取り込んだコミットを `web/note-types.js` に記録）。最初の型は、救急外来初療（A04）・外来初診（A01）・病棟入院時（A05）・病棟の経過（A06）・退院時サマリ（A08）・コンサルト依頼（B02）・申し送り（B06）。症例の入力は1回の診察の事実なので、**A06・A08・B02・B06 は多くの欄が「（未入力）」になる**（作文で埋めない）。欄にどの入力が入るかの表は `docs/enhancement-plan.md` の 7.3
- 組み立ては決定論（AI を使わない）。入るのは、症例の入力と、医師が採用した項目だけ。採用していない項目は入らない。未入力の必須欄は「（未入力）」、条件つきで中身のない欄は出さない。**日付・患者ID・氏名は入力していないので空欄**（`［日付］［患者ID］［氏名］`）。先生が症例に書いた自分のアセスメントは、「先生のアセスメント（入力）」として、AI の印なしで入る
- 草案の計画は「予定・検討（実施の記録ではありません）」と明示し、実施済みの欄には入れない。採用した項目が、選んだ型に入る欄を持たないときは、画面に件数を出す（黙って捨てない）
- 採用した項目には「〔AI草案〕」の印と、出どころの印（`[推論]` など・書籍の頁・出典の一覧）が付く。コピーのとき、2つを別々に外せる（数値の【出典未確認・要確認】は常に残る）。実際のカルテに貼るのは先生で、貼る前に確認・修正する
- 画面は読み取り専用。**送信・保存・書き出し・印刷・共有はしない**（コピーだけ）。採用の選びはタブのメモリだけで、閉じると消える。Worker に記載の API はなく、D1 への書き込みも増えない

**架空症例の作成の細目（作成者の案。実装済み。変えたいときは言ってください）**

- 入口は「症例」の画面の「書籍から架空症例を作る」。入力は、テーマ（病名・症候）・場面・難しさ（標準／紛らわしい鑑別あり／複合問題）・学ばせたいこと（任意）・落とし穴の有無。患者の情報ではないので、テーマと「学ばせたいこと」にも識別情報のガードをかける（画面・サーバー・保存の入口）
- モデルは、書籍を検索して、その病態の**典型的な所見・検査値の動き・経過・鑑別・落とし穴**を確かめ、**新しい**症例を作る。出力は固定の見出し: 導入文／症例の入力用（年齢・性別・場面・主訴と経過・バイタル・所見・検査・既往・内服の7項目）／所見の表（項目・値・根拠。根拠の頁は引用が示す）／見立て／落とし穴／教訓／書籍に見つからなかった点。**診断は「見立て」にだけ書かせ、最初は畳む**
- **書籍の症例文は写さない**。プロンプトで禁じ、さらに機械で検査する: 作った症例を、その質問で見つかった節の本文と、文字と数字だけで比べ（全角・空白・記号の違いは無視）、**30字以上続けて一致**した箇所があれば、画面で、頁と一致の長さつきで警告する（Worker の `final.overlap`。検査の結果は往復と一緒に保存する）
- 数値は例示。**閾値・用量は書かせない**。画面は、用量らしい数値・閾値らしい比較・日付らしい文字を警告する（例示の検査値と区別しきれないので、警告だけ）。識別情報らしき文字があれば警告し、コピーを止める。数値の突き合わせと薄い表示は付けない（作った症例の数値は例示で、書籍の主張ではない）
- 「この症例を症例モードに入れる」で、症例の入力用の7項目だけが、症例モードの症例に入る（**見立ては入れない**。選択肢に合わない値は空欄にして、画面に出す）。そのあと、自分のアセスメントを書いて、草案との差、記載の下書きに進める（訓練の循環）
- **Modules 用の下書き**: clinical-modules の訓練症例（`drills/*.toml`）の `[[case]]` の形（id・title・tags・intro・key・pitfall・lesson・source）のテキストを作り、コピーできる。`[case.answers]`（フローの質問ID・選択肢IDに紐づく）と `[case.expect]` は作らない。所見の表と見立ては、変換の材料としてコメントで添える。id・key・source は `[要変更]` `[要変換]` `[要照合]`（出典の台帳IDへの置き換えは Modules 側）。Modules の 600 字の上限を超える欄は注意を出す。**書籍との重なり・識別情報らしき文字があるときは、コピーを止める**（内容は確認できる）。Modules のリポジトリは変えない（変換を助ける道具は Modules 側の将来の仕事）
- 画面は読み取り専用で、送信・保存・書き出し・印刷・共有はしない（コピーだけ）。作成の依頼は、会話の往復に付けて保存される（`payload.create`。識別情報らしき文字があれば保存を断る）。D1 への書き込み先は増えない
- プロンプトの書きぶりは、**本物の API でまだ確認していない**。使ってみて、書籍の症例に寄っていないか（重なりの警告の出方）、診断が導入文に漏れていないかを見る

**会話の保存の細目（作成者の案。実装済み。変えたいときは言ってください）**

- 保存の単位は、1往復（質問・回答・引用の印・見つかった節・数値の突き合わせ）。完了した往復だけ。回答の途中で止まったもの（縮退）も、見えている範囲で保存する
- **識別情報の確認を通した質問は保存しない**（画面は送らず、サーバーも質問に識別情報らしき文字があれば保存を断る）
- 最後のやりとりから**30日**で自動的に消える（`CONVERSATION_RETENTION_DAYS`。仮の値。`"0"` で自分で消すまで残る）。「会話」の画面から、1件ずつ・すべて消せる
- 上限: 会話 200 件（超えたら最も古いものから）、1会話 100 往復
- ログには出さない。保存したものを読むのは、アクセストークンを持つ本人の画面だけ

**実装済み（段階1。作成者の案。変えたいときは言ってください）**

- **場面・症候の質問での入力（試作）**: 「症例」の画面の年齢・性別・場面の下に、場面と症候（救急外来 × 胸痛・腹痛・失神など12、外来初診 × 発熱の計13）を選ぶと、その流れの質問が段階ごとに出る。中核の質問を前に、残りは「ほかの項目」に畳む。選択・多選択・数値（単位つき）・時刻・短い文。年齢と性別は症例の欄を使うので重ねて聞かない。性別によって出る質問（女性のみなど）は、症例の性別で出し入れする
- **中核の未入力を出す**: 「中核の質問 n/m 入力済み」と、未入力の中核の一覧（押すとその質問へ移る）。**入れていない項目は「未確認」で、陰性にしない**。送る文には「未入力の中核項目（n件。未確認）」を付ける。**数値は記録するだけ**（色・正常範囲・閾値の判定なし）。鑑別・危険・検査の提案はここでは出さない（規則を取り込んでいない）
- 答えは、症例の `structured`（文）としてモデルに渡り、書籍の検索の手がかりにも使う。識別情報のガードは画面・サーバー・保存の入口の全部で `structured` にもかかる。上限は 6000 字（描画した文の大きさ。貼り付けの上限ではない）。貼り付けの入口（上の 6 の決定）は、**段4a の「文章から取り込む」**（下）。症例の既存の欄の文字数の上限（API の大きさの上限）は変えていない

- **問題ごとの書籍の根拠**: 問題カードの「書籍の根拠（どこを見たか）」に、採用した草案の引用の頁と、先生が「書籍を引く」（問題の名前だけで検索）から残した頁が並ぶ。残すのは題名・頁・節の名前だけ（本文は残さない）。後の日の記録・退院時サマリーの診断ごとに出る（**書籍が記載の内容を支える確認ではない**。「出どころの印」を外したコピーには出ない）。AI に書籍を引かせない
- 通信先は、記録の画面は `/api/records` と、LLM を呼ばない `/api/search`（問題の名前だけを送る）。草案は、これまでどおり `/api/ask`

| # | 問い | 決定 |
|---|---|---|
| 1 | 段5の接続先 | **clinical-casebook**（Modules ではない）。Modules は訓練のままで、往復の経路は作らない。架空症例でも接続できる |
| 2 | 範囲 | **送る向きだけ＋架空症例の印**。Casebook から RAG へ戻す向き（Casebook の症例を RAG が読む）は作らない。架空症例は、Casebook に「架空症例」として入り、実症例と混ざらない |

**実装済み（段5。作成者の案。変えたいときは言ってください）**: 症例の記録から Casebook への**送る向き**。設計と限界は `docs/enhancement-plan.md` の 8.17。**書き込みは増えない**（`case_records` の文書に、送信の状態 `casebook` が増えるだけ）。**通信もしない**（Casebook は別のオリジンなので、クリップボードと貼り付けで運ぶ）。

- **使い方**: 記録の画面の「Casebook へ送る（試作）」（折りたたみ）。送る項目を選び（初めは、まだ送っていない・送れる・AI の草案でない項目が選ばれている）、新しい症例か既存の症例（Casebook の症例コード）かを選び、「パケットを作ってコピー」を押す。Casebook の一覧の「Playbook から受け取る」か貼り付け欄に貼り、Casebook の確認画面で「取り込む」を押す。取り込んだら、RAG の「取り込みました」を押して、送信済みの印（と、新しい症例の症例コード）を記録に残す
- **新しい症例のとき**: 年齢（歳）・性別・場面（救急／入院）を症例から入れておく（直せる）。**実症例か架空症例かは、毎回先生が選ぶ（既定なし）**。架空症例を選ぶと、Casebook では架空症例として作られ、J-OSLER の登録の候補と集計から外れる。取り込んだあとに実症例へ変えることはできない。**外来の症例は送れない**（受診日の暦日が要る。RAG は暦日を持たない）
- **送る項目**（すべて決定論。AI を使わない。先生が書いたもの・採用したものを、記録にあるとおりに）: 救急の入力（主訴と経過・バイタル・身体所見と検査は経過の文、既往・内服と先生のアセスメントはメモ）／問題／**診断（先生が確度を選んだ問題だけ。「可能性が高い」は疑いとして。「確定」は確定。確度が空欄なら診断は送らない。「除外」は Casebook に対応する種類がないので送れない）**／評価・計画・推移・コール基準・入院時の欄（メモ）／日ごとの文（経過）。**計画は、「計画（予定・検討）」「計画（実施の記録）」など状態を文に書いたメモで、「開始した治療」にはしない**
- **送らないもの**: 検査値・バイタルを Casebook の検査項目に当てはめた項目（対応表がないため。入力した文章は経過として送る）、病着からの時刻（経過分）、場面・症候の質問の答えの文面、課題、中間サマリー・退院時サマリーの欄、退院時の薬、主病名・副病名の区分、書籍の頁。画面にも書いてある
- **AI の草案から採用した項目**は、AI の印を付け、`source: "ai"` で送る。RAG でも Casebook の確認画面でも、初めは選ばれない
- **送れない項目**（理由の種類だけを出し、文は繰り返さない）: 識別情報らしき文字、日付（暦日。経過の表現に直す）、中身がない文。Casebook の匿名化の検査が止める形（元号の略記の日付など）も、先に止める。1つの文が Casebook の上限（500字）を超えるときは、文の切れ目で番号つきの複数の項目に分ける（切り捨てない）。**1回に送れるのは 100 項目まで**
- **同じ項目を何度送っても、Casebook に2つできない**: 項目の ID は、記録ごとの種（`seed`）と項目の名前から決まる。**送信済みの印は「取り込みました」を押したときだけ**付く（コピーしただけでは付かない）。送信後に直した項目は「送信後に直した」と出て、初めは選ばれない。選ぶと**新しい項目として**送る（Casebook にある前の項目は変わらず、残る）。症例コードと印を消して、別の新しい症例として送り直すこともできる
- **Casebook 側の変更（T059、A-070）**: パケットの封筒に、新しい症例だけの任意の欄 `synthetic: true` を足した。**Casebook を先に更新してから**、架空症例の印を付けて送る（古い Casebook は、この欄つきのパケットを全体拒否する）。Playbook は印を付けない（P078で契約の写しだけ同期した）
- **試験**: `worker/test/casebook.test.ts`（符号化と ID が Casebook 自身の出力と同じ文字列〔`tests/vectors/casebook-handoff.json`〕、項目、パケット、再送、画面が何も送らない・保存しない固定）。`CASEBOOK_DIR` に Casebook の作業ツリーを渡すと、Casebook 自身の読み取りと匿名化の検査も通す。`tests/e2e/ui_casebook.py`

**年齢を歳の整数にしたことについての注意**（決定 4。作成者から）
- 入れてよい質問の約束が「年代」から「年齢（歳の整数）」になった（`CLAUDE.md`・画面の帯の下のヘルプ・API の約束を直した）。年代より個人に近い情報になる。**モデルにも整数の年齢が渡り、会話（30日）と記録（60日）に残る**。稀な年齢と稀な病名・職業などの組み合わせは、これまでどおり一般化する（2.2）。画面には、90歳以上は「90」と入れてよいと案内を付けた（作成者の案。変えたいときは言ってください）
- 以前の保存（「70代」など）は、そのまま読める。**Casebook に送るときは歳の整数が要る**ので、古い症例は症例の画面で直す

**まだ実装していないもの・限界**: Casebook から RAG へ戻す向き、検査値・バイタルの構造化項目、病着からの経過分、治療の開始・中止の項目、課題・サマリー・退院時の薬、外来の症例。**本物の Casebook の画面での取り込みの確認は、まだない**（作成者は、Casebook 自身の読み取り・匿名化の検査・取り込みの処理で確かめた）。

## 2. 入力の約束の細目（作成者の案から始めたもの。1b のとおり実装済み）

決定 3 の「氏名・ID は入れない」を、画面とサーバーで守れる形に落とす案。

### 2.1 入れないもの

- 氏名、患者 ID・カルテ番号・診察券番号、生年月日、住所、電話番号、メールアドレス、保険証・マイナンバー、施設名・病棟名・担当者名
- **日付は絶対日付ではなく経過日数で書く**（「3日前から」「入院2日目」）。画面の文言で促すだけで、**ガードは日付を検出しない**（1b の 1。clinical-modules の識別情報の警告と同じ扱い）

### 2.2 稀な組み合わせ

年代・性別・稀な病名・地域・職業の組み合わせは、1 つずつは識別情報でなくても、特定につながりうる。稀な症例は、主要所見を一般化して聞く（例: 具体的な稀な病名を出さず、病態で聞く）。ここは機械では検出できないので、入力欄の近くの文言で促す。

### 2.3 ガード（画面とサーバーの両方）

- 画面: 送信前に検査し、見つかったら種類の名前を示して「直す／このまま送る」を選ばせる（入力は消さない）。clinical-modules の `web/id-guard.js` と同じ考え方
- サーバー: `/api/ask` と `/api/search` の入口でも同じ検査をし、見つかって承認の印がなければ送らずに 400 を返す。これは事故を防ぐ網で、悪意のある回避を防ぐものではない
- 網にかかるもの: 8桁以上の数字の並び、電話番号らしき並び、ID/MRN の後ろの数字、メールアドレス、「患者ID」「カルテ番号」「診察券」「生年月日」「患者氏名」「マイナンバー」「保険証」「電話番号」「郵便番号」「〒」の語
- **氏名は検出しない**（敬称つきの語も。1b の 1）。氏名は「患者さん」「奥さん」など普通の語と区別できず、誤検出が多い（clinical-modules の 2026-10-15 の判断と同じ）。検出できないことを前提に、2.2 と画面の文言で補う
- 実装: 画面 `web/id-guard.js`、サーバー `worker/src/idguard.ts`。2つの実装は `tests/vectors/idguard.json`（臨床の文面が通る例を含む35例）で縛る。サーバーが見るのは質問と、履歴のうちユーザーの発言だけ（モデルの回答は文献番号などを含むので見ない）。一度確かめて送った質問は、履歴として送り直すときも確認済みの印を引き継ぐ
- 網にかからなくても、識別情報を入れてよいことにはならない

### 2.4 保存の範囲（会話・評価の質問以外は保存しない）

- Worker は質問・回答を保存しない `[確認]`: DB の部品（`worker/src/db.ts`）は読み取り（`all`）だけで書き込み経路がなく、ログ出力は `search.ts` の `console.warn` 1か所（トークナイザが使えないときのエラー文。質問は出さない）だけ。会話は端末のメモリだけ（アクセストークンだけ端末に保存）
- Cloudflare 側のプラットフォームのログ設定は、リポジトリからは分からない `[未確認]`
- 質問や回答を保存する機能（履歴・お気に入りの本文・書き出し）を足すときは、実臨床由来の質問が含まれうるので、先に医師が決める。端末内のしおり（書籍と頁だけで、質問文は含めない）は、この制約に収まる案
- 例外（1c）: 評価の質問は D1 に置く。評価の結果は保存しない
- 例外（1e）: **症例の記録は D1 に保存する**（表 `case_records`。最後の更新から60日で自動的に消え、画面から「終える」で消せる。識別情報の検査は入れ子の文字すべてにかかる。日付は入れない）。
- 例外（1d・1e）: **会話（質問と回答）は D1 に保存する**。症例モードで付けた症例も、往復の一部として同じ表に入る（識別情報らしき文字があれば保存を断る）。識別情報の確認を通した質問は保存しない。場面・症候の質問への答え（`payload.case.intake`。1e）も同じ往復に入り、入れ子の文字まで識別情報の検査にかかる（貼った原文は保存しない。日付は直したあとの文だけ）。30日で自動的に消え、画面から消せる。書き込みの一覧は `worker/test/conversations.test.ts` で固定している（`usage_daily`・`eval_questions`・`conversations`・`conv_turns`・`case_records` 以外への書き込みと、質問を出すログは、テストが落ちる）

### 2.5 外へ出る経路

質問 → Worker → Anthropic の API。Web 検索をオンにすると、モデルが作る検索語がさらに外の検索に出る。そのため、プロンプトに「**Web 検索の検索語には、症例固有の値（年齢・検査値）を入れず、一般化する**」を足す案。README には「API 経由のデータは既定では学習に使われません」とあるが、最新の規約・保持の設定は、医師が確認する。

### 2.6 画面の常時表示

全画面の上に「**参考情報・患者を特定する情報は入れない・最終判断は医師**」を出す。clinical-modules の帯（「訓練・データ収集用（架空症例のみ）」）とは別の文言にする。消すボタンは作らない。

### 2.7 回答の姿勢

- 出力は「論点・根拠・反証」。特定の患者への指示の形（「〜を投与せよ」）にしない。診療判断の代行はしない（現行のプロンプトにもある）
- **引用のない文は、見た目で区別する**（書籍の記述ではなく、モデルの推論や一般知識であることが分かるように）
- 数値は、書籍で確認できたものだけを無警告にする。確認できないものは強調する（決定論の突き合わせ。`docs/enhancement-plan.md` の T1-6）
- **患者固有の用量計算（体重あたりの量、mL/hr）はモデルにさせない**。式と必要な入力だけを示し、「要検算」と添える。現行のプロンプトは投与速度（mL/hr）まで具体化するよう求めている（`worker/src/prompt.ts` の「回答の型」）ので、直す対象
- 書籍間・ガイドライン間の食い違いは、版・年を示して並べる（現行どおり）
- 末尾に「**施設プロトコルは別途確認**」を添える（決定 4）

## 5. 施設プロトコルを入れる余地（未決）

決定 4 のとおり、いまは入れない。**入れる日が来たときに、先に決めること**を残す。

1. **許可・機密区分**: 院内の資料を、外部のサービス（Cloudflare）に置いてよいか。施設の規程を、医師が確認する
2. **種別と出どころ**: 書籍と混ざらないように、種別（`books.kind`）に `protocol`、チャンクの出どころ（`provenance`）に `institution` を足す。タグは `[施設]` を付ける。書籍の引用と、施設の運用の引用は、画面で別の色・別のラベルにする
3. **版の管理**: 施行日・改訂日・改訂者・有効期限を持つ。期限切れは検索結果に出すが、警告を付ける
4. **優先順位**: 施設プロトコルと、書籍・ガイドラインが食い違うとき、隠さず両方を並べる。どちらを採るかは、画面の裏で決めない
5. **リポジトリには入れない**: 施設の内部プロトコルは、clinical-modules の `CLAUDE.md` の「絶対に入れない」のとおり、リポジトリに入れない。入れるのは、本人の非公開の D1 だけ
6. **取り込みの手順**: 書籍と同じ取り込み（`ingest`）を使えるか、書式（`docs/FORMAT.md`）に表や分岐図をどう載せるかを、実物を見て決める
