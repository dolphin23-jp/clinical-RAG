# 転写 Markdown の書式（取り込みが前提にしていること）

実際の1章（レジデント向け腎臓病マニュアル第4版の第1章）を読み取って決めた仕様です。**ここに無い書き方は、取り込みが黙って誤解する可能性がある**ので、
`python3 -m ingest validate` の警告を必ず見てください。1章ぶんのサンプルから逆算した仕様なので、別の本を足したら書式差を `validate` で確認し、必要ならここと `ingest/parse.py` を直します。

## 1. ファイル単位

1ファイル = 1章。ファイル名は自由。章 ID は `<book_id>:chNN`（`chapter_no` から）。同じ章を再度 `build` すると、その章だけ置き換わります（冪等）。

```yaml
---
title: 第1章 …
book: レジデントのための腎臓病診療マニュアル 第4版     # 書名（版を含む）
chapter_no: 1
chapter_title: ...
pages: 1-67                                            # 印刷された頁番号
sections:                                              # 「<英字> <題名> (p.<開始>-<終了>)」の文字列で書く
  - "A 腎臓病診療の特徴 (p.1-3)"
  - "B 腎臓病診断のプロセス：臨床推論 (p.3-15)"
text_reliability: 転写者1名による読み．…全文の二重照合は未実施．…   # 「未実施」「未確認」を含むと全検索結果に警告が付く
notes: ...
---
```

節の文字（A, B, …）が本文の `# …　A 題名` の文字と一致し、頁範囲が本文の頁マーカーと矛盾しないことを `validate` が確認します
（`E_SECTION_MISSING` / `W_SECTION_UNDECLARED` / `E_PAGE_OUT_OF_RANGE`）。

## 2. 本文の約束

| 要素 | 書式 | 取り込みでの扱い |
|---|---|---|
| 節 | `# ... A 題名` または `# 第1章 G 題名`（A〜M などの英数字 1〜3 字 + 題名） | 節 ID・題名・著者に紐づく。**両方の書式を許容**（後述） |
| 見出し | `## / ###` | 親節の「章節パス」（`B > 鑑別診断 > 感度`）になる |
| 頁 | `出典ページ: p.X` / `p.X-Y`（**頁が変わった箇所にだけ**出す） | 以降のチャンクへ**持ち越す**。見出しで頁をリセットしない |
| メタ引用 | `> 節:` `> 転写注記:` `> 出典:` `> 内容:` `> 記法:` `> 所属:` で始まる引用 | 索引から除外（メタ情報） |
| 囲み（本文の引用ブロック） | 上記以外の `> ` | **本文として索引化**（囲み記事の本文を失わないため） |
| 図 | `**図N-M　題**`、任意で画像、`- キャプション:`（原本の逐語）、`- 図中の文字・構造:` `- 図の意図:`（転写者の記述） | キャプション = `book`、後2つ = `transcriber`（`figure_aid`）。`(※本項は原本の逐語ではなく…)` の定型句は除去 |
| 表 | Markdown 表。`(表の注: …)` は転写者注 | 列数不整合を警告。注は `transcriber_note` |
| 参考文献 | `n)` または `a)` で始まる行、`[PMID: 12345678]` | 節ごとに文献テーブルへ。PMID は PubMed へのリンクに使う |
| 引用番号 | `<sup>1)</sup>` / `<sup>1,2)</sup>`、脚注 `注1)` | 参照先が無いと `W_CITE_UNRESOLVED` / `W_FOOTNOTE_UNRESOLVED` |
| 節末の著者 | 行全体が `（著者名）`（2〜40字、数字・コロン・`注` を含まない） | 節の著者として記録（検索結果に表示） |

## 3. 実章で見つかった注意点（転写ツール側の改善候補）

1. **頁マーカーは節の途中でしか出ない**（`出典ページ` は頁が変わるときだけ）。見出しの直後に頁表記が無い箇所が多数あり、
   見出しで頁をリセットする実装だと 30 チャンクが「頁なし」になった。→ 持ち越しルールに修正済み。引用の頁は検索結果の頁マーカーから引くため、
   **頁が変わる箇所の出力漏れがそのまま誤引用につながる**。転写ツールで頁変更の出力漏れが無いか、`validate` の `W_PAGE_REGRESSION` を見る。
2. **H1 の書式が章内で混在**（A〜F は `# …　A 題名`、G〜M は `# 第1章 G 題名`）。両方を許容するようにしたが、どちらかに統一すると事故が減る（`I_H1_STYLE_MIXED` が情報として出る）。
3. **転写者の記述と原本の逐語が同じ見出しの下に混在**（図の「図中の文字・構造」など）。索引と引用で区別できるよう `provenance` を分けたが、
   書式上の目印（行頭ラベル）が崩れると区別が失われるので、ラベルは機械的に固定してほしい。
4. 数値・表・式の転写は**拡大再照合した箇所だけが信頼できる**とフロントマターに書かれている。`numeric_critical` は用量・閾値らしい記述を印付けするが、
   見逃しも過検出もある（例: `P<0.05` を誤検出しないよう調整済み）。用量表・補正式を含む章はまだ見ていないので、見つけ次第サンプルを下さい。
5. 参考文献は `n)` と `a)` の 2 方式があり、PMID の有無もまちまち（82 件中 40 件に PMID）。文献は既定では検索対象外。

## 4. `validate` が出すコード

| レベル | コード | 意味 |
|---|---|---|
| error | `E_DUP_ID` `E_EMPTY_CHUNK` `E_NO_PAGE` `E_PAGE_OUT_OF_RANGE` `E_IMAGE_MISSING` `E_SECTION_MISSING` | 取り込みを止める（`--force` で強行可。非推奨） |
| warn | `W_PAGE_REGRESSION` `W_FOOTNOTE_UNRESOLVED` `W_CITE_UNRESOLVED` `W_TABLE_COLS` `W_SECTION_UNDECLARED` `W_NO_AUTHOR` `W_RELIABILITY` | 取り込みは通る。回答時に警告として運ばれるものがある |
| info | `I_H1_STYLE_MIXED` `I_IMAGE_UNCHECKED` `I_TRANSCRIBER_FLAG` `I_CHUNK_NOTE` | 転写者が「要確認」と書いた箇所など。該当節が引用されると画面に既知の問題として出る |

## 5. チャンク種別

`body`（本文）/ `key_points`（要点）/ `references`（参考文献、既定で検索外）/ `figure`（キャプション）/ `figure_aid`（転写者の図説明）/ `table`。
本文チャンクは 700 字前後（最大 950 字）で、見出し・頁をまたがないように分割します。親（返却単位）は 3500 字以内で最も大きい見出し祖先です。

## 6. 自動 OCR（EbookText Studio `全文.md`）

章ファイルではなく本1冊ぶんの OCR 出力は `ingest.ocr_convert`（または `scripts/import_ebooktextstudio.py`）で章形式に変換してから取り込みます。
フロントマターに `source_format: auto-ocr` が付き、`text_reliability` に「照合は未実施」が入るので、全結果に警告が出ます。
頁の決め方・節の作り方・古い出力の扱いは README の「1b」と `ingest/ocr_convert.py` の冒頭コメントを参照してください。
実測した出力の癖: 頁終わりマーカーの 0.7〜6%（4冊で 2/287・8/142・9/157・1/58 件）が読み違い（11・1058・19 等）、表は Markdown 表（`tables/` に原画像）、図の中の文字は `<details>` で入る、
見出し（`##`）は OCR の推定で本文の断片が混じる、古い版の出力には頁マーカーも見出しも表も無い。

## 7. 変換ログ（章ごとの照合状況）→ `issues`（`ingest conversion-log`）

転写を原本の頁画像と照合した状況（章ごと・節ごと）を、`issues` に `source = 'conversion-log'` として載せます。検索は `source` が `ingest` でない issue を、その章・節の結果に付けて返す（`worker/src/search.ts`）ので、**一部しか照合していない章や、不一致が残っている節は、その本文の横に警告として出ます**（転写者の `要確認` と同じ運び方）。書籍ごとの「要確認 N件」（`open_issues`）にも数えられます。

変換ログを作る側の出力の形は、ここでは決めません（実物を見ていないため）。**この道具が読む形は、次の JSON lines（1行1件）**で、作る側の出力からこの形へ直す小さな変換が別に要ります。

```
{"chapter": 2, "section": "B", "pages": "12-14", "status": "mismatch", "note": "用量表の1行が原本と不一致（修正待ち）"}
{"chapter": 2, "status": "partial", "note": "表だけ拡大再照合"}
{"chapter": "ch02", "section": "A", "status": "verified"}
```

| キー | 意味 |
|---|---|
| `chapter` | 必須。章の番号（`2`）、`ch02`、または章 ID（`fx:ch02`）。データベースにある章だけ |
| `section` | 任意。節の英字（`B`）。その章にある節だけ。なければ章全体 |
| `pages` | 任意。`12` か `12-14`。メッセージに入るだけ |
| `status` | 必須。`verified`（照合済み）／`partial`（一部だけ）／`unverified`（未実施）／`mismatch`（不一致が残っている） |
| `note` | 任意。1行・120 字まで。読む人に知らせたいこと |

- `verified` は何も書かない（警告することがないため。件数は表示する）。ほかは `warn` を1件ずつ書く: `CL_PARTIAL`／`CL_UNVERIFIED`／`CL_MISMATCH`
- **`note` に書籍の本文を入れられない**: 章の本文と 20 字以上重なる `note` は取り込みを止める（著作物を、書籍でない場所へ運ばないため）。何を確認すべきかを書き、書籍が何と言っているかは書かない
- **1行でも問題があれば全体を取り込まない**。問題は行番号つきで全部出す（書き込みはない）。`--check` は読んで確かめるだけで書かない
- 同じ章を取り込み直すと、その章の `conversion-log` の行だけが置き換わる（ほかの章・`ingest`・手で足した行は触らない）。**`ingest build` で章を作り直すと、その章の issue は全部消える**ので、変換ログはあとで取り込み直す
- 使い方: `python3 -m ingest conversion-log --db OUT.sqlite [--check] BOOK_ID LOG.jsonl`。D1 へは、本を書き出すとき（`ingest/export_sql.py`）に `issues` として一緒に載る
